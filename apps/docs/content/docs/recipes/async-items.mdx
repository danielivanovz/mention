title: Async search
description: Fetch suggestions with debouncing, cancellation, loading, empty, and error states.
---

Pass a fetcher as `items`: `(query, signal) => Promise<readonly TItem[]>`. The fetcher supplies the search results; Mention does not apply the array filter to its response.

## Connect a search endpoint

This component expects `/api/users?q=...` to return an array of users with `id`, `username`, and `name`. Implement that endpoint in your application or replace its URL and response validation to match your API.

```tsx
"use client";

import { Mention, useMentionContext } from "@danielivanov/mention";
import "@danielivanov/mention/styles.css";

type User = { id: number; username: string; name: string };

function isUser(value: unknown): value is User {
  return (
    typeof value === "object" &&
    value !== null &&
    "id" in value && typeof value.id === "number" &&
    "username" in value && typeof value.username === "string" &&
    "name" in value && typeof value.name === "string"
  );
}

async function searchUsers(
  query: string,
  signal: AbortSignal,
): Promise<readonly User[]> {
  const response = await fetch(
    `/api/users?q=${encodeURIComponent(query)}`,
    { signal },
  );
  if (!response.ok) throw new Error(`Search failed: ${response.status}`);

  const data: unknown = await response.json();
  if (!Array.isArray(data) || !data.every(isUser)) {
    throw new Error("Unexpected search response");
  }
  return data;
}

function SearchError() {
  const { status } = useMentionContext<User>();
  return status === "error" ? (
    <p role="alert">Could not load suggestions. Edit your query to try again.</p>
  ) : null;
}

export function MessageInput() {
  return (
    <Mention.Root<User>
      items={searchUsers}
      getKey={(user) => user.id}
      getLabel={(user) => user.name}
    >
      <Mention.Input aria-label="Message" />
      <Mention.Popover aria-label="People">
        <Mention.List<User>>
          {(user) => (
            <Mention.Item value={user}>
              <strong>{user.name}</strong>
              <span> @{user.username}</span>
            </Mention.Item>
          )}
        </Mention.List>
        <Mention.Loading>Searching…</Mention.Loading>
        <Mention.Empty>No people found</Mention.Empty>
      </Mention.Popover>
      <SearchError />
    </Mention.Root>
  );
}
```

`useMentionContext<User>()` reads the existing Root session. A standalone `useMention()` call would create a separate session, so it is not the way to read that Root's status.

## Set the debounce delay

Async requests debounce for **150 ms** by default. Set `debounceMs={300}` on Root to wait longer, or `debounceMs={0}` to start immediately. This delay applies only to fetchers, not synchronous item arrays.

## Cancel unnecessary work

Forward the supplied `AbortSignal` to `fetch`. When the query, channel, or fetcher changes, or the session closes, Mention aborts the previous request. Forwarding the signal lets the network client stop work that is no longer needed.

The core also discards late results when a fetcher ignores cancellation. It hides previous results as soon as the query changes and will not commit an obsolete item. Cancellation saves work; it is not the sole protection against stale results.

Keep the fetcher reference stable when its behavior has not changed: declare it outside the component, as above, or use `useCallback` with its real dependencies. A new fetcher reference starts a new request.

## Show each outcome

- `Mention.Loading` renders while a request is pending.
- `Mention.Empty` renders after a successful query with no results.
- `status === "error"` identifies a rejected active request. The example shows this outside the listbox through a child of Root.

Return `[]` for no matches. Throw for request, response, or parsing failures. Typing a new query starts another request; there is no built-in retry control.

Synchronous arrays may be created during render. The core derives their filtered results directly; fresh array references are not prohibited. Memoize expensive data preparation when your application benefits from it.

## Verify request ordering

Make one query slow and a later query fast. Confirm that the fast query's results remain current when the earlier request finally resolves, including when a test fetcher deliberately ignores the signal. Also test a rejected request and a successful empty response.
